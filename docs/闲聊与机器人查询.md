# 闲聊、位置查询与助手回复

工作台首页的 **AI 助手 → 对话与查询** 页签显示用户输入与助手回复。文字输入可以在该页签底部直接发送，也可以在“输入与候选 → 文字输入”中发送；语音仍使用原来的开始录音、停止并识别按钮。收到闲聊或查询回复后会自动切换到对话页签。

对话页签提供“查询位置”“查询状态”“查询电量”三个快捷入口，它们与文字提问走相同的实际链路：

```text
文字输入 / 语音识别结果
  → /ai/parse_task（Qwen 判断闲聊、查询、任务或追问）
  → 需要查询时请求 /ai/query_robot_state
  → 根据实时遥测生成事实答复
  → 助手回复显示在对话页签
```

闲聊由本地模型生成回复；查询的最终事实答复由程序根据服务响应生成，不采用模型编造的坐标、电量或运行状态。当前提供文字显示，没有新增自动语音播报。

## 更新与启动

本次接口升级为 **robot_interfaces 0.4.0**，扩展了 `ParseTask`、`TaskParseReport`，增加了 `QueryRobotState`。只重启旧界面或只修改提示词不足以启用功能。关闭旧工作台及旧解析/音频处理节点，在 Ubuntu 实际使用的源码仓库拉取更新后，在对应 ROS 工作空间重新构建：

```bash
source /opt/ros/humble/setup.bash
colcon build --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard
```

在现有启动命令里保留自己的模型、设备、部署等参数。工位数量、名称、别名与物料以“系统设置”的实际配置为准，示例点位不构成默认配置。

工作台自动启动新增的 `ai_edge robot_state_query_node`。如果使用 `start_backend:=false` 只连接外部服务，则需要在外部启动更新后的解析节点和查询节点：

```bash
ros2 run ai_edge robot_state_query_node --ros-args \
  -p odom_topic:=/odom \
  -p status_topic:=/robot/status \
  -p battery_topic:=/battery_state \
  -p max_data_age:=2.0
```

工作台自动启动时，查询节点会沿用 `robot_odom_topic`、`robot_status_topic`、`robot_battery_topic` 和 `robot_telemetry_timeout` 的实际配置。

## 查询内容与边界

| 提问 | 查询类型 | 实际数据来源 |
|---|---|---|
| 你现在在哪里？ | `ROBOT_LOCATION` | `nav_msgs/Odometry`：坐标、朝向、坐标系、采样时间 |
| 机器人现在是什么状态？ | `ROBOT_STATUS` | `robot_interfaces/RobotStatus`：状态、活动任务、错误码 |
| 电量还剩多少？ | `ROBOT_BATTERY` | `sensor_msgs/BatteryState.percentage` |

位置查询报告遥测坐标系中的坐标，不擅自将里程计坐标称为地图坐标，不猜测对应的工位名称。没有数据、数据过期、时间不同步、无效测量或服务未连接时，会在对话区域直接说明原因。仿真部署的数据来自仿真遥测，不代表真实硬件的位置。

`RESPONDED=5` 表示已完成一轮对话或查询；其 `success=false` 表示没有生成可执行任务候选，不是闲聊失败。只有 `READY` 的 `success` 为 true。音频处理阶段 `INTERACTION_COMPLETED=11` 表示回复已经保存，原有请求 ID 查询也能恢复回复。

闲聊和只读查询不会清空当前等待补充的任务，也不会自动加入草稿或触发执行。任务仍需核对草稿并明确确认。“重新开始”和“取消任务”会清除待补充对话；取消已经运行的机器人任务仍使用现有执行取消流程。

## 验证

已使用现有 `qwen3.5:2b` 验证闲聊、位置查询、状态/电量查询和自定义工位导航；通过真实 ROS Action/Service 往返及 Qt 回复显示验证。位置测试使用隔离的受控遥测数据，没有操作真实机器人。

回归入口：`ai_edge/test/test_interaction.py`、`ai_edge/test/test_interaction_ros.py` 和 `robot_visualization/test/test_conversation_ui.py`。后两者分别需要构建后的 ROS 接口和 PySide6。
