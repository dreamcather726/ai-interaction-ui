# 复杂文本指令与预期编排

“输入与候选 → 文本指令”中输入后点击“发送文本指令”。本轮回复留在当前页面，动作候选在下方显示；加入草稿后核对并确认执行。对话面板只显示本轮，不保留连续聊天记录，不会因为新回复回到别的页签。

以下五条按本次只读检查到的资料库测试：工位ID为 `1`、`2`、`3`，别名为 `A`、`B`、`C`；物料ID为 `x`、`B`。`B点`和`B物料`按实体类型区分。这里的点位数量仅对应这组测试配置，程序不预设点位数量或名称，也不要求连续编号。

## 1. 连续搬运两种物料后返回

```text
去1号点拿X物料，到2号点放下；再从2号点拿B物料到3号点放下，最后空车返回1号点。
```

预期8个动作：去1 → 在1抓x → 去2 → 在2放x → 在2抓B → 去3 → 在3放B → 回1。

两段搬运衔接时已经到达2号点，不再自动增加一次“导航到2”。

## 2. 物料送回与空车返回分别处理

```text
把B物料从2号点送到3号点放下，再把同一个B物料从3号点送回2号点放下，最后小车回1号点。
```

预期8个动作：去2 → 抓B → 去3 → 放B → 在3抓B → 去2 → 放B → 空车去1。

“送回”包含再次抓取物料，不会被误解成只让小车返回。

## 3. 显式列出独立动作

```text
导航到3号点，抓取B物料，导航到1号点，放下B物料，抓取X物料，导航到2号点，放下X物料，最后返回3号点。
```

预期8个动作，逐条对应原文；放下B后在1号点抓取x，再运到2号点。

## 4. 多点巡行

```text
先去3号点，再去1号点，再到2号点，最后回3号点。
```

预期4次导航：3 → 1 → 2 → 3，无抓取和放下动作。

## 5. 必须追问，不能猜物料

```text
去1号点取一个物料，到2号点放下，最后回3号点。
```

预期保留路线并询问具体物料，不能默认选择x或B。回答 `X物料` 时，只补充当前任务缺失的物料，路线保持不变。

## 模型与程序分别验证

模型输出采用精简参数，只摘录原文中的实体名称，由程序映射实际ID。未知实体留空并追问；普通闲聊历史不参与映射。完整动作还要经过白名单与抓持、位置顺序校验。

能够完整匹配的明确指令先作确定性编排，任何未识别的后半句都会让规则整体放弃，交给模型理解，不静默执行前半句。其它表达、闲聊与查询继续使用配置的本地模型。

真实模型回归脚本使用独立临时资料库，包含五个自定义工位和三种物料，用于覆盖多次搬运、不同物料、原路送回、否定指令、查询范围及缺参。不会改写用户资料库，也不会下发机器人运动：

```bash
python3 src/ai_edge/test/live_command_scenarios.py --report /tmp/complex-commands.json
python3 src/ai_edge/test/live_command_scenarios.py --model-only --report /tmp/model-only.json
```

第一条验证实际处理链路，第二条绕过明确指令规则，单独验证模型抽取与实体映射。报告记录每条输入、预期动作、实际结果和采用的处理路径；不能把规则通过数当成模型通过数。

本次完整链路的11条通用指令和上述5条实际配置指令均通过对照，文本输入经ROS解析后保存8步草稿的流程也已验证。测试只保存未执行草稿，并使用隔离遥测验证查询，没有驱动真实机器人。单独依赖小模型时，未明确放下等含糊表达仍不稳定，因此这类明确可识别的情形由程序追问拦截。
