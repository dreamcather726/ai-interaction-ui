# 部署配置与验证

保留五个 ROS 包、现有 `ros2 run`／`ros2 launch` 命令及通信端点。
正式工作台部署使用 `robot_visualization/config/` 下的分层配置：

| 层级（后者覆盖前者） | 用途 |
| --- | --- |
| 节点默认值 | 独立启动兜底 |
| `common.yaml` | 公共模型、推理参数、超时、路径及接口 |
| `simulation.yaml`／`real.yaml` | 部署差异 |
| 显式指定的 `local.yaml` | 本机模型路径、设备地址及数据目录 |
| launch 参数 | 本次启动临时覆盖 |

`local.yaml` 不自动搜索，须通过 `local_params_file` 指定。
它不参与源码提交或安装打包；工位和物料继续在资料库维护，配置只指定资料库路径。

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch robot_visualization dashboard_sim.launch.py \
  local_params_file:=/absolute/path/local.yaml \
  data_root:=/absolute/path/runtime \
  model:=qwen3.5:4b num_ctx:=8192 num_predict:=1024 \
  asr_ncpu:=2 start_microphone:=false
```

实机使用 `dashboard_real.launch.py`。可用 `common_params_file`、`params_file` 替换前两份配置。
所有公开工作台配置项均可作为同名 launch 参数临时覆盖；空 launch 参数表示沿用配置。
数值、布尔值和字符串数组按参数类型校验；字符串保持原样，例如名为 `true` 的模型仍是字符串。
未知参数、重复 YAML 键、错误类型、非有限数值及不合理的超时关系会导致启动失败。
需要清空可选字符串时在本机 YAML 中设置 `""`。

## 路径规则

`data_root` 相对启动目录解析；其他相对数据路径和模型路径相对最终的 `data_root` 解析。
规则适用于音频、资料库、草稿库、下发记录、ASR 模型、回放 WAV 和带目录的 ASR Python 路径。
`~` 展开为当前用户目录；绝对路径保持其含义。单独的 Python 命令名通过 `PATH` 查找。
正式部署建议始终指定绝对 `data_root`，避免改变启动目录后产生另一份运行数据。
模型路径未配置时保留现有自动检测行为。

配置在启动时合并、校验和解析，再传入工作台，由工作台传给本次创建的后台节点。
修改外部配置后重启生效；修改包内配置后重新编译并加载安装环境。暂不提供运行时热更新。
直接 `ros2 run robot_visualization dashboard --ros-args ...` 保留独立参数入口，不自动加载这些 YAML。

## 启动日志

终端和 `~/.local/state/ai_interaction/dashboard_*.log` 记录配置来源、模型、部署模式、绝对路径及代码加载位置。
接口包版本取已安装的 `robot_interfaces/package.xml`，任务协议版本取实际加载的 `TaskSpec` 默认值，两者分别显示。
仅连接模式同样保存配置诊断。

工作台只为新创建的节点传参。对已有外部节点，日志会警告“本次配置未应用、参数一致性未验证”；
工作台不会接管或重启这些进程。如需应用配置，手动重启对应外部节点。
需要核对实际值时，在同一 ROS Domain 中执行，例如：

```bash
ros2 param get /parse_task_node model
ros2 param get /parse_task_node num_ctx
ros2 param get /asr_node ncpu
ros2 param get /audio_processing_node parse_timeout
ros2 param get /task_draft_node database_path
```

## 分批验证

从源码根目录运行下面的离线配置规则测试，无需 ROS、Qt、模型或设备：

```bash
PYTHONPATH=ai_edge:robot_visualization \
  python3 -m unittest discover -s robot_visualization/test -p test_configuration.py -v
```

ROS 配置集成测试须先构建并加载 ROS 2 工作空间，然后执行：

```bash
python3 -m unittest discover -s src/robot_visualization/test -p test_config.py -v
python3 -m unittest discover -s src/robot_visualization/test -p test_backend_parameters_ros.py -v
QT_QPA_PLATFORM=offscreen \
  python3 -m unittest discover -s src/robot_visualization/test -v
```

后台参数测试构造实际 ROS 节点，仅替换 ASR 模型加载；最后一条包含 Qt 和 ROS 客户端测试，不加载真实 ASR／LLM。
缺少依赖时的跳过须单独报告，不能算作通过。真实模型及 SIM 执行验收单独显式运行。
回归应比较失败用例清单，确保没有新增失败。
