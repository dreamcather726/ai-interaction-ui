# 第一次任务：把一段录音识别成文字

任务名称： 把一段录音识别成文字

建议周期： 2～3 天

运行位置： PC 机 Linux 虚拟机中的 ROS 2 工作空间，沿用项目现有 ROS 2 发行版

岗位文件夹： `~/ai_edge_engineer`（AI 端侧工程师），直接建在 Linux 用户主目录 `~` 下，作为本岗位的 ROS 2 工作空间 对接人员： 组内接口工程师

## 一、本次目标

在 `~/ai_edge_engineer/` 工作空间中接入语音识别节点，沿用项目现有 ROS 2 环境和接口规范。节点使用现成的本地语音识别模型，读取接口工程师提供的一段录音，通过 ROS 2 Service 返回识别文字，并保存一份文字结果供核对。

开发语言可以使用 Python，但交付物必须是能在 ROS 2 工作空间中构建、通过 `ros2 run` 启动的功能包，包含节点、依赖声明和可执行入口注册。

## 二、数据与接口要求

**香橙派麦克风录音 → 接口工程师提供录音文件 → ROS 2 识别节点 → 接口工程师调用识别 Service 获取文字。**

第一次仍用录音文件作为音频输入，由 ROS 2 参数指定文件位置，通过 Service 触发识别和返回结果。音频与格式说明统一向接口工程师获取。岗位工作空间统一命名为 `ai_edge_engineer`；功能包、节点及业务接口与现有项目规范保持一致，下文相关名称作为示例，开始前与接口工程师确认。

### 接口工程师需要提供的录音

两段录音可分别说“你好，机器人”和“查询当前状态”。

如果原始录音格式不同，由接口工程师转换后提供，不能只改扩展名或采样率标记。本岗位收到后读取 WAV 文件的采样率、声道和位宽，并试听确认；有问题统一反馈接口工程师。

### ROS 2 功能包与接口

`Trigger` 的请求为空，音频路径由节点参数提供，不放在请求中。其响应字段见 [ROS 2 官方接口定义](https://github.com/ros2/common_interfaces/blob/rolling/std_srvs/srv/Trigger.srv)。本次只练习单句识别，不设计新的自定义消息。

### 构建、启动与调用示例

先加载项目现有 ROS 2 环境，在 Linux 用户主目录下创建工作空间及数据目录：

```Bash
cd ~
mkdir -p ai_edge_engineer/src ai_edge_engineer/samples ai_edge_engineer/models/asr ai_edge_engineer/results
cd ai_edge_engineer
```

然后在 `src/` 下准备功能包，将录音和模型放入对应目录，再进行构建。目录安排如下，`ai_asr` 为功能包名称示例：

```Plain Text
~/
└── ai_edge_engineer/
    ├── src/ai_asr/       # ROS 2 功能包
    ├── samples/          # 接口工程师提供的录音
    ├── models/asr/       # 本地识别模型
    └── results/          # 识别结果
```

构建后会生成 `build/`、`install/` 和 `log/`。两个终端均先加载项目现有 ROS 2 环境，工作空间统一使用 `~/ai_edge_engineer`；包名和节点名如与现有项目不同，同步调整命令并记入操作步骤文档。

终端一：构建功能包并启动节点。

```Bash
cd ~/ai_edge_engineer
colcon build --packages-select ai_asr
source install/setup.bash
ros2 run ai_asr asr_node --ros-args -p audio_path:=samples/001.wav -p model_path:=models/asr -p output_path:=results/001.txt
```

上述相对路径以 `~/ai_edge_engineer/` 为启动工作目录解析，也可改用实际文件的绝对路径；若通过项目 Launch 启动，应在其中明确配置路径。节点应声明这三个参数，并注册可执行入口。

终端二：加载工作空间，检查节点和服务，再触发识别。

```Bash
cd ~/ai_edge_engineer
source install/setup.bash
ros2 node list
ros2 service list -t
ros2 service call /ai/recognize_audio std_srvs/srv/Trigger "{}"
```

正常时应能看到对应节点和识别服务，例如 `/asr_node`；调用后返回成功状态与实际识别文字，并在约定路径生成结果文件。节点在处理请求后继续运行，等待下一次调用。

识别第二段录音时，先停止节点，再修改启动参数中的输入与输出文件为 `002.wav`、`002.txt`，重新启动并调用服务。本次不要求动态修改参数。

结果文件只保存实际识别文字。示例语句不能写死在节点中，也不能读取配套答案作为识别结果。

## 三、需要做的事情

只补充两种基本错误：文件不存在、格式不符合约定。通过服务返回 `success=false` 和具体原因，并在节点日志中记录；节点保持运行，不返回成功或生成假结果。

本次完成 ROS 2 节点中的单段录音识别。音频流 Topic 接入、大模型理解和语音回复放到后续任务。
