## 任务基本信息

- **任务名称：** 制作一个显示识别状态和文字的小窗口

- **建议周期：** 2～3 天

- **运行位置：** PC 机 Linux 虚拟机中的 ROS 2 环境，使用虚拟机桌面显示窗口

- **岗位文件夹：** `~/robot_visualization_engineer`（机器人可视化工程师），直接建在 Linux 用户主目录下

- **唯一数据对接人：** 组内接口工程师

## 一、本次目标

创建一个 ROS 2 界面功能包和节点，订阅接口工程师提供的两个 Topic，在一个简单窗口中显示“识别状态”和“识别文字”。

**数据链：AI 端侧生成识别状态和文字 → 接口工程师原样转发 → 本岗位 ROS 2 界面节点订阅 → 窗口显示。**

接口工程师只负责接入和转发，不承担语音识别、格式转换或识别结果判断。本岗位仍仅对接接口工程师，不绕过统一接口获取数据。

本次只做一个能收数据的小窗口，为后续运行状态和任务全过程展示打基础。地图、视频、完整任务流程和交互按钮放在后续任务。所有数据与接入问题统一向接口工程师获取和反馈，不直接接入 AI 端侧节点、香橙派或其他组。

## 二、数据与接口要求

### 向接口工程师要什么数据

AI 端侧每秒发布一次当前状态与文字，接口工程师收到后原样转发，不自行重发缓存。本岗位订阅使用可靠、易失、深度 10 的 QoS，与发布侧一致。一次只展示最新结果，重复收到同一文字时更新显示即可，不不断追加相同行。

第一次可先接接口工程师转发的 `DEMO` 消息，演示消息由 AI 端侧提供；真实识别完成后使用同样的 Topic 验证，不直接调用 AI 端侧服务。消息的 `data` 字段可参考 [ROS 2 String 官方定义](https://github.com/ros2/common_interfaces/blob/rolling/std_msgs/msg/String.msg)。

### 窗口显示什么

状态为等待、识别中或失败时，不显示上一条文字为本次成功结果；状态和文字可能先后到达，仅在 `DEMO` 或 `SUCCEEDED` 且文字非空时展示有效结果。收到未知状态时显示“未知状态”及原值，不能默认显示正常。

数据中断后仍可保留最后一次文字，但必须标注“历史结果，数据已中断”；再次收到消息后恢复当前显示。源节点或转发节点停止都可能导致中断，本岗位只显示“接口数据中断”，不能凭此判断哪一端故障；这里的“正在接收”也不代表底层机器人在线或硬件正常。

### ROS 2 功能包与启动示例

先加载项目现有 ROS 2 环境，再创建工作空间：

```Bash
cd ~
mkdir -p robot_visualization_engineer/src
cd robot_visualization_engineer
```

在 `src/` 下准备功能包和界面节点，安装并记录所用界面依赖。目录为：

```Plain Text
~/robot_visualization_engineer/
└── src/robot_monitor_ui/    # ROS 2 界面功能包
```

以下是在代码完成后的目标启动方式；包名和入口如沿用项目已有名称，同步调整命令并写入操作步骤文档。

```Bash
cd ~/robot_visualization_engineer
colcon build --packages-select robot_monitor_ui
source install/setup.bash
ros2 run robot_monitor_ui monitor_ui_node
```

界面启动后应出现 `/monitor_ui_node`，窗口可以正常关闭。ROS 2 消息处理与界面事件循环要能同时运行，不能因为等待消息而卡住窗口；关闭窗口时同时停止该节点。

联调时，由接口工程师启动原样转发节点，并协调 AI 端侧提供演示或真实消息。本岗位在另一个已加载 ROS 2 环境的终端检查数据：

```Bash
cd ~/robot_visualization_engineer
source install/setup.bash
ros2 node list
ros2 topic list -t
ros2 topic echo /interaction/asr_text std_msgs/msg/String
```

双方使用相同的 ROS 2 发行版和项目通信配置，包括相同的 `ROS_DOMAIN_ID`。若终端也收不到数据，先将检查结果反馈接口工程师，不直接修改其数据源。

## 三、需要做的事情

本次不做输入框、确认、取消或机器人控制。界面不能把演示文字、空消息或上次结果显示成当前真实识别成功。

## 四、提交与验收

**最终提交一份《第一次任务\_机器人可视化与监控工程师\_操作步骤\.md》，将 ROS 2 功能包、界面截图、接口说明和启动步骤纳入文档，代码作为附件或提供可访问位置。**

每一步写清“执行什么、应看到什么、实际结果是什么”。验收人员应能照文档打开窗口，看到接口工程师提供的两条不同文字，识别演示模式，并复现中断与恢复。窗口在等待或中断时仍可操作、关闭后节点退出。

演示模式可先验收界面开发；真实语音联调须注明结果来自香橙派录音，经 AI 端侧和接口工程师传递。真实链路暂不可用时保留待办，不用演示截图代替真实联调结果。
