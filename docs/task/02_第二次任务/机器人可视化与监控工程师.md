# 第二次任务：机器人可视化与监控工程师

**本周目标：把第一周的 ASR 文字窗口升级为任务理解监控窗口，展示“原文 → 解析进度 → 任务候选/追问/失败”。**

先读[本岗位知识清单](../../知识点/第二周/机器人可视化与监控工程师｜第二周专业知识自学清单.md)。接口岗位已经增加异步编排，窗口负责展示与输入，不直接请求 Ollama，也不重复实现语义校验。

## 一、需要展示的内容

| 区域 | 最少内容 |
|---|---|
| 输入与身份 | 原始文字/实际 ASR 文字、入口类型、request_id |
| 流程状态 | 等待 ASR、识别中、等待 LLM、理解中、校验中、最终结果 |
| 结构化候选 | 任务类型、物料、取货/送货或导航站、返回要求与返回站 |
| 需要补充 | 已知候选、缺失字段、clarification_question |
| 错误与历史 | error_code、原因、最近至少 20 个请求，可选择查看 |

没有的字段显示“未提供”，不能拿上一条请求的数据补空位。页面标明“候选待人工核对”，不显示机器人已完成。布局保持清楚即可，不要求复杂美化、地图或相机。

## 二、对接数据和文字入口

沿用或新增 `ros2 run robot_visualization monitor_ui`。接入[共同端点表](README.md#二先统一接口与数据)：ASR 状态/文字、解析状态/结果，以及输入受理回执。

增加一个单行/多行文字输入框和“解析”按钮，发布 `UserText` 到 `/interaction/user_text`；为新输入生成新编号并填写四个身份字段，文字 1～4096 字。窗口保留所发文字与编号，收到该编号的 RECEIVED 只显示已受理，等待真正的解析结果。

请求处理中暂时限制重复点击；本地发布成功不代表桥接节点已接收，未收到受理/结果时需有等待超时提示，且不能假定远端已取消。输入空白不发布。

## 三、接收、缓存与渲染

- 每份请求按 request_id 独立保存原文、状态、ASR 与解析结果。新请求显示空候选，不能混入旧结果。
- 状态序号按来源、boot_id 和请求过滤；已终结请求不被旧进度改回“处理中”。ASR 与解析状态来自不同来源，分别保存后决定展示，不把两个来源序号直接比较。
- 以接口提供的终结结果为准显示 READY、NEED_CLARIFICATION、UNSUPPORTED、FAILED、CANCELED。`success=false` 不一定是崩溃，例如缺参是正常业务结果。
- 历史只保留最近至少 20 条，选择记录时原文、编号、候选与错误同步切换。

使用 QTimer 非阻塞处理短 ROS 回调，或沿用现有工作线程＋Qt 排队信号。不得在 GUI 主线程等待模型 HTTP；关闭时停止自己的定时器、节点或线程，不关闭同伴单独启动的服务。
