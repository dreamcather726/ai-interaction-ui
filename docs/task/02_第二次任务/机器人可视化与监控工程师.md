# 第二次任务：机器人可视化与监控工程师

## 数据链路图：

```text
窗口开始／停止录音 → 接口工程师统一提供的采集控制入口
  → 设备采集、PC 接收、AI 识别
  → 统一清单中的状态／文字／查询接口 → 窗口显示本段结果
```

## 任务基本信息

- **任务名称：** 在识别窗口加入录音操作和本次结果显示
- **建议周期：** 第二周，5 个工作日；具体日程见[共同安排](README.md#三5-个工作日安排)
- **运行位置：** PC 机 Linux 虚拟机的 ROS 2 Humble 环境，虚拟机桌面显示窗口
- **岗位文件夹：** 沿用第一次 `~/robot_visualization_engineer`；接入本项目时复用 `src/robot_visualization`
- **唯一数据对接人：** 组内接口调用工程师

## 一、本次目标

沿用第一次显示识别状态和文字的小窗口，增加“开始录音”和“停止并发送”按钮。用户在窗口连续录两段不同内容，无需切换文件路径，即可看到本次录音的处理阶段、真实文字或具体错误。

优先复用本项目 PySide6 工作台中已有控件和 ROS 客户端，不要求重新实现完整界面。第一次窗口尚未验证的，先补齐订阅、等待和正常退出，再接按钮。

本岗位负责用户操作、消息关联和显示，不安装或调用模型，不读取“最新录音”重复触发 ASR，不从终端日志推导状态。统一通过接口工程师交付的公开清单接入；清单中已有 `/ai/` Topic 可以直接订阅，无需再要求复制为 `/interaction/`。接口问题仍统一反馈接口工程师。

本周不做任务确认、任务取消、硬件急停、地图视频或搬运进度。录音开始／停止只控制采集，不表示机器人执行或停止了运动。

## 二、数据与接口要求

### 向接口工程师要什么数据

取得[共用接口清单](README.md#2-三方共用接口清单)、现场版本、QoS、录音来源与关联规则、各阶段超时、部件状态发布频率及过期阈值。控制入口使用两个 `std_srvs/srv/Trigger`；文字和状态使用当前公共自定义消息，不能继续按两个无关联的 `String` 拼接本次结果。

窗口订阅 `/ai/request_status`、`/ai/audio_state`、`/ai/asr_text`，按需补查 `/ai/query_audio`；采集与模型状态使用接口工程师提供的 `ComponentStatus` 和心跳。只有阶段发生变化时才收到阶段消息是正常情况，不能把它当周期心跳计算掉线。

开始成功时音频请求 ID 尚未生成，停止响应只有 `success`、`message`，没有结构化 ID 字段。先与接口工程师落实本段关联方案，再实现显示；结合约定采集来源的结构化消息、会话和上下文关联当前片段，并与控制结果核对。无法唯一归属时显示“本次结果未确认”，不根据最新到达的文字猜测。

### 窗口显示什么

窗口至少包含：开始按钮、停止并发送按钮、采集／模型就绪提示、当前处理阶段、本段关联标识、识别文字和错误说明。普通页面展示清楚中文含义，完整 ID 和错误码可放详情。

| 实际情况 | 显示要求 |
|---|---|
| 未就绪或模型加载 | 显示等待原因，开始按钮不可用；未知不显示正常 |
| 正在请求开始 | 显示等待响应，禁止重复开始 |
| 开始响应成功 | 显示采集已启动，并结合麦克风部件状态更新；不显示识别完成 |
| 停止响应成功 | 显示已停止发送、等待接收确认；不把它当 AI 受理 |
| 文件保存成功／AI 受理 | 分别显示已保存／已受理，等待识别 |
| `WAITING_ASR`／`RECOGNIZING` | 显示等待 ASR／正在识别，不伪造百分比 |
| 本段 `RecognizedText` 成功 | `success=true`、`status=SUCCESS` 且文字非空后展示实际文字；`ASR_COMPLETED` 表示本周处理结束 |
| 无语音、失败或超时 | 显示真实原因或结果未确认；上一段文字不能当本段结果 |
| 未知阶段或数据中断 | 显示未知值／连接未确认，保留内容时标为历史 |

本次录音开始时将旧文字移为历史或清空当前结果区，状态和文字先后到达时按同一来源关联。`ASR_COMPLETED` 先到但文字未到时可显示“识别已完成，等待文字”，再补查，不使用旧文字填充。`confidence=-1` 隐藏分数。

### 重复、迟到与恢复

一次只允许一段录音操作；按钮根据请求、采集和处理状态启用／禁用。停止请求发出后不得因再次点击而重发同一音频；不要因为等待超时自动重新开始或提交。

同一音频按四个来源 ID 关联，阶段按 `(source_node, boot_id, request_id, event_seq)` 去重和处理顺序。旧片段、旧进程、旧查询响应不得覆盖当前片段；历史恢复结果须注明对应录音。麦克风部件状态超过 3 秒未更新时显示未确认，不能靠倒计时推测已停止；ASR 活性阈值与界面等待预算第一天共同记录。

晚加入或消息缺失时，对已知音频 ID 调用 `QueryAudio`。新查询 ID 放在 `request_id`，目标音频 ID 放在 `target_request_id`；只有 `success`、`found` 和 `asr_available` 满足时才能读取识别结果。查到记录不等于识别成功，未找到或节点重启后无记录时明确提示。未知本段 ID 时先反馈接口工程师，不自动取最近一条历史记录。

### ROS 2 功能包与启动示例

以下假设本仓库位于 `~/ai-interaction-ui/src`，使用本项目现有界面功能包：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --packages-up-to robot_visualization --cmake-args -DAMENT_CMAKE_SYMLINK_INSTALL=OFF
source install/setup.bash
export ROS_DOMAIN_ID=71
```

`71` 为示例域，须与设备和后端现场登记值一致。复用工作台时沿用 `robot_visualization/requirements.txt` 中固定的 PySide6 版本，安装方式见[工作台使用说明](../../前端工作台_使用说明.md)。本周由接口和 AI 工程师分别启动采集、接收、ASR 和 `enable_semantic:=false` 的编排；工作台仅连接已有节点：

```bash
ros2 run robot_visualization dashboard --ros-args -p start_backend:=false
```

不使用默认受管后台另启完整语义链。若沿用第一次独立窗口，保留其实际包名与入口，在个人文档中给出完整 `ros2 run` 命令，不要求迁移所有页面。无论采用哪种窗口，都只连接同一套现场节点。

另一个已加载相同环境的终端检查接口，持续监听命令按 Ctrl+C 结束后再执行下一条：

```bash
ros2 service type /audio/start_recording
ros2 service type /audio/stop_recording
ros2 topic info /ai/asr_text --verbose
ros2 topic echo /ai/asr_text robot_interfaces/msg/RecognizedText
```

终端也收不到数据时，将节点、类型、Domain 和 QoS 检查结果交接口工程师；不自行连接设备或新增旁路模型调用。

## 三、需要做的事情

1. **复核第一次窗口。** 确认可启动、订阅、等待、标注 DEMO、显示中断并正常退出；保留已验证的能力。
2. **接入录音按钮。** 异步调用开始／停止服务，显示请求中、已接受和拒绝原因，防止重复点击；服务不可用、超时或采集故障时仍能操作和关闭窗口。
3. **展示本次结果。** 按统一规则绑定本段来源、状态与文字，完成连续两段不同内容实录；旧结果不显示为新结果，模型只做 ASR 时不等待语义候选。
4. **验证异常与恢复。** 配合无语音、AI／ASR 不可用、超时、数据中断、重复消息与迟到旧消息测试；已知 ID 时补查真实快照，未知或无记录时明确提示。
5. **完成界面退出。** ROS 通信与 Qt 事件循环分离，不能同步等待模型或 Service 卡住窗口。关闭时清理本窗口创建的线程与进程；外部启动的后端按共同停止步骤处理，不擅自结束他人的节点。

主要负责共同验收 W2-01～W2-08 中操作、关联和显示部分。模型和设备暂不可用时可先用明确标注 DEMO 的消息完成显示开发，真实联调仍须单独验收。

## 四、提交与验收

**最终提交一份《第二次任务_机器人可视化与监控工程师_操作步骤.md》，包含 ROS 2 功能包位置、界面依赖、真实启动命令、字段来源与状态映射、按钮规则、超时参数、界面截图和异常恢复记录。**

每一步写清“执行什么、应看到什么、实际结果是什么”。附两段实录对应的请求标识、窗口结果和共同联调记录位置；截图注明真实／DEMO、环境和版本，受控附件交付，不将个人录音及运行数据提交源码。

**验收标准：** 验收人员按文档打开窗口，不修改文件路径即可完成两段不同实录，并看到各自真实状态与文字；录音发送、文件保存、AI 受理和 ASR 完成有明确区别。等待、失败、中断和无语音不会展示为成功；重复点击不重复提交，旧结果和查询响应不覆盖新录音。界面在模型推理和通信异常期间仍可操作，关闭后本窗口正常退出。真实链路未验证的部分保留待完成，不能用演示截图替代通过。
