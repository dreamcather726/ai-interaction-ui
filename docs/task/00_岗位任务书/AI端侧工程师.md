# AI 交互组｜AI 端侧工程师任务书

**开发周期：** 2 个月（8 周）
**岗位人数：** 1 人，与接口调用工程师协作
**人员基础：** 零基础，采用“先文字任务、再语音输入、最后实机反馈”的开发方式
**岗位定位：** 负责 PC 虚拟机中的语音交互、本地模型推理与 AI 交互节点，将用户自然语言转为受约束的候选任务，并根据真实执行结果进行回复。
**通信方案：** 程序和模型统一部署在 PC 机的 Linux 虚拟机中，模块之间统一使用 ROS 2 Topic、Service 和 Action。

---

# 一、项目条件与本岗位目标

本岗位完成的业务链：

**采集语音 → 识别文字 → 解析 Action 提取候选参数 → 缺参澄清 → 准备 Service 校验 → 请求用户确认 → 发送执行 Action Goal → 接收真实反馈 → 播报 Action 回复。**

音频采集、ASR、模型推理、TTS 和交互主控均在 PC 虚拟机内运行，通过 ROS 2 通信。**模型节点在虚拟机进程内直接调用本地推理库，对外提供 ROS 2 接口；模型权重、词表和参数保存在虚拟机可访问的本地路径。**

**开发重点：** 完成虚拟机中的模型接入、语音识别、任务解析与 ROS 2 功能联调，验证模型正确加载、输出符合协议，以及节点异常时能够正确处理。

---

# 二、部署方案与职责边界

ASR/TTS 使用现成模型与本地推理库。各节点均在 PC 虚拟机运行，模型调用与交互主控分开处理，保持查询和取消功能可用。首期先完成按键录音闭环，自动 VAD 随后接入；唤醒词、复杂降噪、回声消除和全双工对话作为扩展。

首期使用现成模型，不安排从零训练 ASR/TTS/LLM。

本岗位不负责 SLAM、Nav2、视觉模型训练、相机标定、抓取空间定位、机械臂规划、电机控制或整车运动安全。涉及这些能力时调用接口，语音回复不得推断或编造执行结果。

---

# 三、核心工作任务

## 重点细节

1. **先文本后语音。** 第 2 周先用手输文字跑通候选任务与确认，减少 ASR、模型和机器人接口同时出错的排查难度。

2. **接入虚拟机中的本地模型。** 确认模型路径、运行依赖、中文任务理解及结构化输出，记录模型名称、版本与调用方式；重点验证任务参数和错误处理是否正确。

3. **模型只提取候选类型与参数。** 程序负责生成任务 ID、绑定会话并转换为公共消息类型；接口调用工程师负责执行许可和实际调度。

4. **用户确认由程序执行。** 模型输出“已确认”不构成确认操作；确认必须来自用户对当前任务内容的明确操作或回复，改参后重新确认。

5. **首期不开放独立“抓取”任务。** 抓取、放置是受状态机约束的内部步骤，避免跳过到站、定位和安全条件。用户说“抓这个”时，先澄清到受支持的完整任务。

6. **优先复用视觉 Topic。** 视觉组负责采集与识别，接口调用工程师直接订阅图像和检测结果并显示；本岗位只在需要视觉上下文时订阅结果。真实抓取坐标由视觉定位组提供。

7. **模型输出与节点消息分开。** JSON 可用于模型节点内部解析；校验后转换为明确的 ROS 2 消息字段，不通过任意 JSON 字符串直接驱动执行。

---

# 四、自然语言与任务生成规则

## 首期支持的意图

首期一次会话维护一个候选任务；有运动任务执行时，允许查询和取消，不再自动创建第二个运动任务。“这个”“那里”等指代只有在当前会话中存在唯一、有效且经核对的对象时才能使用，否则澄清。

## 双重校验

- AI 交互节点先检查模型输出能否解析、类型及字段是否合法、工位和物料是否在已同步的名单中，然后构造 `TaskSpec` 消息。

- ASR 的无有效语音或失败结果不进入解析；解析缺参时只澄清，不支持或失败时不准备任务。消息字段、解析结果枚举及关联规则统一遵循独立接口协议第四章。

- 输入按会话和输入 ID 只消费一次，生成任务前保存关联；语音确认及界面按钮绑定当前候选任务、版本和确认上下文，迟到输入不确认新候选。

- 调用准备 Service 进行权威校验；用户确认后才发送执行 Action Goal，由调度节点重新检查任务版本、忙碌、定位、模块健康和数据有效性。交互节点校验通过不代表已经开始执行。

- 模型输出格式错误时最多进行一次受约束修正；仍不合法则返回解析失败，不提交运动任务。

- 对未知额外字段、任意代码、Shell 命令、速度/关节指令、模型自造的坐标和未知工具调用予以拒绝。

- 每次执行尝试先保存下发 ID。Goal 被拒绝时按任务 ID 和下发 ID 查询具体原因；响应丢失时先核对记录，不等待被拒绝 Goal 的 Result，也不得重新生成 ID 反复发送同一请求。

## 播报与停止规则

语音回复应基于调度节点的查询快照、执行 Action 反馈/结果或任务事件 Topic。例如，“等待你确认”“任务已接受”“已到达 A 工位”“抓取失败”“取消请求已发送”“停止未确认”“物料已送达，但返回失败”。只有终态为成功且实际结果满足任务内容时，才能播报“任务完成”。

语音“停止”是普通取消请求，不能替代硬件急停。ASR 识别出明确停止词后直接走取消分支，桌面取消按钮也必须直接可用；TTS 播报期间仍可通过按钮取消。首期采用半双工语音，播报期间不保证识别语音停止，必须向使用者说明此交互限制，不能承诺紧急停止能力。

识别失败、含糊回复、过期或上下文不匹配的输入不触发确认；确认会话超时后作废。TTS 播报时暂停常规录音或丢弃自身回录；确认提示播放结束后再开放该任务的确认上下文并恢复采集，防止机器人将自己的回复或迟到的旧回复当成确认。

# 五、协作接口与协议引用

统一接口见 ROS 2 通信接口协议。任务准备/查询 Service、执行 Action、状态与图像 Topic、消息字段、确认/取消流程、任务状态、QoS 和错误码均在该文件集中维护，本任务书不再重复定义。

本岗位负责音频/识别/模型/播报节点的 ROS 2 接口、交互 Topic，以及任务准备、执行、查询和取消的客户端联调。

协议仍为首期草案。接口变更须同步更新独立协议及公共接口包，经相关工程组评审后锁定版本；岗位任务与验收要求继续以本任务书为准。

# 六、设备接入、视频与异常处理

## 虚拟机设备与模型接入

- 记录音频采样率、声道、编码和实际模型要求；按模型需要转换格式，不默认所有模型输入一致。

- 确认麦克风和扬声器已接入虚拟机，实际完成录音、识别与播放；与视觉组确认摄像头的唯一采集节点及图像话题。

- 确认模型文件路径和运行依赖，实际完成中文任务解析；通过 Launch 和参数文件启动节点，记录正常及错误返回。\.

- 串口等机器人设备由对应工程组提供虚拟机侧驱动接入方式，分别验证节点通信和真实设备反馈。

- 模型权重、录音及测试视频与源代码分开保存，按需要提供版本和获取说明；不默认将个人语音、密钥或大模型文件纳入版本控制。

## 视觉与交互数据

视觉组通过 ROS 2 发布原始或压缩图像，接口调用工程师直接订阅显示。本岗位不增加图像转发节点；通过交互 Topic 发布录音状态、识别文本、AI 回复和候选任务，带会话 ID、任务 ID 及时间戳。

需要根据视觉结果澄清“这个物体”时，必须检查源帧、采集时间、类别与目标 ID；候选不唯一或数据过期时询问用户。检测框与图像的显示匹配由接口调用工程师负责；单目画面不提供天然可靠的三维抓取坐标，本岗位不得从显示框推算运动指令。

# 八、个人交付与验收

## 最终交付

1. PC 虚拟机中的音频采集、ASR、TTS 和播放节点。

2. 虚拟机本地模型推理节点、解析 Action、模型版本及功能测试记录。

3. 预定义任务解析、公共消息转换、缺参澄清与确认会话模块。

4. 任务 Action 调用、事件订阅、查询/取消 Service 调用及真实状态播报模块。

5. 识别文本、AI 回复、候选任务和交互状态 Topic；需要时订阅视觉上下文。

6. ROS 2 Launch、参数文件、节点依赖及简要启动说明、固定测试集和测试记录。交互代码进入既有 `ros2-logistics-interaction`，公共契约进入 `ros2-logistics-interfaces`；整机部署与集成组协作评审。

本次仅编写任务书，上述内容均为后续研发交付要求；不代表已经实现。

## 个人验收条件

- 可以从文字及语音输入生成同一套受约束候选任务；缺参、未知物料/工位、越界指令得到澄清或拒绝。

- 未确认任务不执行，修改参数后旧确认失效；重复请求不造成重复搬运。

- ASR 三类结果、解析缺参与失败、同一识别片段重放、旧确认迟到及下发拒绝/响应丢失均按独立协议第四章用例验证；每个输入只能关联到一次任务准备流程。

- 模型在 PC 虚拟机中实际运行，经 ROS 2 解析 Action 输出候选任务；有模型加载及功能运行记录，节点故障不会触发机器人运动。

- 取消和状态查询可绕过 LLM；明确记录半双工语音及语音停止的限制。

- 只按真实任务事件播报进度和结果，断连显示未知，返回失败不播报整单成功。

- AI 交互数据通过 ROS 2 Topic 发布，不抢占相机；视觉指代使用有效且唯一的目标，并有消息关联与错误处理记录。

## 测试集与共同验收建议

建议第 1 周冻结不少于 40 条文本用例，覆盖正确导航/搬运、同义表达、缺参、未知目标、越界动作、确认/改参/取消和异常输入；另录制不少于 20 条固定语音，覆盖安静及现场噪声环境。分别记录 ASR 文本、意图、参数和最终请求；不能用 ASR 字词准确率代替任务正确率。

与接口调用工程师共同完成不少于 10 次完整实机搬运及至少 1 小时联合运行，覆盖关键阶段取消、通信中断和模块失败。以上为建议测试量；任务正确率和连续运行通过条件由技术负责人在测试前冻结。错误运动请求被执行、未确认即执行、虚报完成和重复执行均须修复后重新验证。

测试记录分别标注静态检查、模拟、虚拟机节点运行和实机联调结果，并附软件、模型及接口版本。

---

**最终岗位目标：** 让用户通过自然语言提出明确、受约束的机器人任务，并通过真实反馈知道任务是否被接受、执行到哪一步、成功还是失败。
