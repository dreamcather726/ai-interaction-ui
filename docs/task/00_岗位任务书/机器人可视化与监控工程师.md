# AI 交互组 \| 机器人可视化与监控工程师任务书

> 数据链路图：原飞书图片未随文档导出，待补充；详见[附件说明](../附件/README.md)。

开发周期： 2 个月（8 周）

岗位人数： 1 人，统一与组内接口工程师对接数据、业务接口和联调

人员基础： 零基础，采用“先模拟数据、再接真实接口、最后实机验证”的开发方式

岗位定位： 建立机器人监控工作台，让用户看清机器人当前运行状态、所在位置、现场画面和整个任务执行过程，知道任务做到哪一步、出现什么问题以及最终是否完成。

通信方案： 沿用现有方案，程序统一部署在 PC 机的 Linux 虚拟机中，模块之间统一使用 ROS 2 Topic、Service 和 Action；本岗位所需数据和操作入口均由接口工程师统一提供。

---

## 一、项目条件与本岗位目标

本岗位需要展示的完整业务链： **用户输入 → AI 解析与任务校验 → 等待用户确认 → 前往取料工位 → 到站及停稳确认 → 识别与空间定位 → 抓取确认 → 前往放料工位 → 放置确认 → 按配置返回 → 反馈实际结果。**

首期沿用已配置的 A/B 工位和有限物料类别。接口工程师统一提供 AI 输入与解析结果、任务校验与执行反馈、机器人状态、地图、视频、识别结果及历史记录。本岗位接入这些接口，将数据组织成用户能够理解的界面。

用户通过工作台应能够回答以下问题：

1. 机器人是否在线，当前处于空闲、执行、等待、异常还是急停状态？

2. 机器人现在在哪里，准备去哪里，规划路径是什么？

3. 当前执行的是哪个任务，已完成哪些步骤，正在执行哪一步，后面还有哪些步骤？

4. 摄像头看到了什么，是否识别到目标，抓取和放置是否得到执行模块确认？

5. 任务为什么停住或失败，是否需要用户确认或人工处理，最终结果是什么？

本岗位以状态与过程展示为核心，不承担大模型部署、任务状态机、SLAM、目标检测训练、相机标定、机械臂控制或底盘驱动开发。

## 二、系统部署与职责边界

**界面范围：** 优先复用 RViz2 显示地图、位姿和路径，使用 Python 桌面界面显示状态、任务流程、视频、告警和 AI 交互信息。两者组成首期监控工作台，支持同屏并排查看；将 RViz2 嵌入同一窗口作为可选优化。网页管理平台、手机 H5、微信小程序和三维数字孪生不纳入本阶段必做任务。

Python 桌面界面优先选用一种成熟框架，例如 PySide6；第 1 周确定后保持统一，不同时开发多套界面。

**节点组织：** 本岗位负责 `monitor_ui_node` 和 RViz2 配置；`ai_interaction_node`、`task_scheduler_node` 和 `robot_state_node` 的业务与接口由接口工程师负责。界面和 RViz2 均按接口工程师提供的接口清单、命名空间及接入配置订阅数据，通过其约定入口提交输入、确认、查询和取消请求。具体节点名称、包名与接口在第 1 周与接口工程师统一。

**接口工程师统一提供的数据与本岗位工作：**

**与现有任务书的衔接：** 《AI交互工程师\.md》中涉及监控工作台的界面开发、布局和显示逻辑，由本岗位承接；接口工程师负责统一数据出口、业务接口、任务执行及联合验收。本岗位仅对接接口工程师提供的接口，不建立第二套调度系统或状态汇总节点。

## 三、核心工作任务

### 重点细节

1. 机器人运行状态总览

工作台顶部持续显示机器人连接状态、当前运行状态、当前任务和主要异常。分别展示导航、视觉、机械臂、底盘及调度模块的状态，避免只用一个“在线”图标代表所有模块正常。

电量、速度、定位状态、急停状态等以接口工程师提供的数据为准。每类数据明确接口来源、原始来源模块和最后更新时间；尚未接入、未知、断连及过期均有文字提示，不使用默认正常值代替。

2. 地图、位姿与路径显示

通过 RViz2 显示接口工程师统一提供的地图、机器人位置与朝向、目标工位和规划路径。所需 Topic、TF、坐标系和配置均向接口工程师确认。提供适合演示的默认视角、机器人跟随视角和图层配置，用户启动后即可识别机器人与 A/B 工位的位置关系。

定位或 TF 异常时显示明确提示；保留的最后位置须标明过期，不能继续呈现为实时位置。不自行生成另一套地图、里程计或规划路径。

3. 任务全过程可视化

以步骤列表或时间线展示完整搬运流程。每个步骤支持“未开始、执行中、等待确认、已完成、失败、取消、跳过”等显示状态；仅使用公共协议实际支持的状态及映射，不自行新增业务状态。按配置不需要返回时，返回步骤明确标为“不需要返回”或“跳过”。

任务详情至少展示任务 ID、取放工位、物料、当前步骤、已用时间、各步骤开始与结束时间、执行反馈及最终结果。当前步骤突出显示，完成步骤保留记录，异常步骤显示原因和来源。

用户输入尚未生成有效任务时，展示输入或请求标识及校验状态；获得任务 ID 后关联到同一条交互记录。非法输入、忙碌冲突和下发拒绝应显示具体原因。

进度以调度模块反馈为准。首期优先展示“当前步骤 / 总步骤”和已完成步骤，不按固定时间推进流程、不编造完成百分比或预计完成时间。已完成步骤数不等于运动距离进度，也不等于剩余耗时。

4. 现场视频与识别结果显示

订阅接口工程师统一提供的图像和检测结果，显示实时画面、物料类别及有效的检测框。检测结果与画面应能够按时间戳或约定标识对应；无法对应时提示结果过期或暂不叠框，避免把旧检测结果画到新画面上。

识别到目标、定位有效、抓取成功和放置成功分别显示。抓放成功必须采用接口工程师提供的、包含真实执行确认的结果，检测框出现不能直接代表任务成功。

视频通过接口工程师提供的 ROS 2 图像接口接入，视频来源和底层接入问题统一反馈给接口工程师，不自行采集或打开 USB 摄像头。视频断流或冻结时明确显示最后画面时间及异常提示，不让静止画面伪装成实时视频。

5. 用户交互与操作反馈

提供任务输入、任务确认、取消任务和查看详情入口；语音输入状态、识别结果和 AI 回复统一由接口工程师提供，本岗位负责展示。确认前显示解析后的取料工位、放料工位和物料信息，便于用户核对。

按钮按真实任务状态启用或禁用。点击后显示“请求已提交”“等待响应”“已接受”或“已拒绝”等反馈，防止连续点击造成重复请求；任务防重和业务校验由接口工程师负责。

取消操作显示“取消请求已提交”及后续处理状态，收到调度模块明确反馈后再显示取消结果。界面按钮标为“取消任务”，不得标为硬件急停；紧急停车和运动保护由底层系统负责。

6. 异常告警与任务历史

告警至少包含发生时间、关联任务、来源模块、问题描述和已知的处理建议。对导航失败、目标缺失、抓取失败、任务超时和通信中断使用用户能理解的中文说明，并保留错误码供排查。

提供历史任务列表与详情查询，可按任务 ID、时间和结果查看完整步骤记录及失败位置。记录由调度侧保存，接口工程师统一提供查询入口，本岗位负责展示与导出；界面日志用于排查显示问题，不替代真实任务记录。首期导出任务摘要和步骤记录即可，不要求保存全部视频或制作视频回放系统。

## 四、界面组织与异常处理

1. 首期界面布局

默认界面优先展示普通用户需要的信息，接口原始消息和调试日志放在详情中。状态使用文字配合颜色和图标，不能只依赖红绿颜色区分。地图、任务、状态和视频支持同屏查看，不要求用户频繁切换页面才能理解当前任务。

2. 必须落实的处理规则

ROS 2 数据接收与界面刷新分离，不能因视频解码、等待 Service 响应或加载历史记录而阻塞整个窗口。图像队列和界面日志设置容量限制，积压时优先显示最新画面；任务步骤与终态记录由调度侧补查，不能随图像一起丢弃。

刷新周期、数据过期阈值和视频显示指标在第 1 周按真实发布频率与虚拟机性能确定并记录。验收时按冻结的参数测量，不将低频正常数据误判为断连。

## 五、协作接口与协议引用

沿用《AI交互工程师\.md》引用的《ROS 2 通信接口协议 V1\.0》。任务准备与查询 Service、执行 Action、状态与图像 Topic、确认及取消流程、消息字段、QoS 和错误码均以公共协议为准，本任务书不另行定义一套接口。

当前文件夹未提供独立协议正文，具体接口名称和字段需在第 1 周与接口工程师核对，不能将示意名称视为已落实接口。

第 1 周与接口工程师共同完成以下对接清单：

1. 每个显示字段对应的数据来源、消息类型、单位、坐标系、发布频率及过期判断方法。

2. 用户输入、解析结果、确认请求、任务 ID 和任务最终结果之间的关联方式。

3. 任务步骤和界面文案的映射，任务快照、执行事件与历史记录的查询方式。

4. 图像与检测结果的对应方式，以及无画面、无目标和结果失效时的显示规则。

5. 确认、取消、重复点击、请求超时、拒绝原因查询及界面重连的处理方式。

6. 模拟与实机的数据来源切换方式；模拟运行时在界面明显标注“模拟模式”。

本岗位负责界面侧的接口需求、订阅与调用适配、模拟显示和验证记录；接口工程师负责统一接口清单、数据接入、公共协议评审及上游协调。接口缺失、字段不足、数据异常或版本变更时，统一向接口工程师提交问题，由其协调并给出结果；本岗位不直接联系其他组取数或接入其内部接口。

接口工程师提供的数据应保留原始来源模块、采集时间和有效性信息，界面据此识别过期和故障，不能只用接口节点在线代替底层模块正常。不通过解析终端日志、大模型文字回复或新增旁路业务服务获取关键执行状态。

## 六、8 周推进安排

排期前提： 8 周覆盖本岗位的界面开发和统一接口接入。先按与接口工程师约定的契约，用模拟数据完成界面与异常逻辑，接口工程师提供真实数据后逐项切换；若第 6 周真实接口仍不可用，应记录缺失项、影响和跟进时间，统一交由接口工程师协调。模拟闭环只能验收显示与接入逻辑，不能替代实机最终验收。

## 七、个人交付与验收

1. 最终交付

2. Python 监控界面和 monitor\_ui\_node，包含运行状态、任务全过程、视频、交互、告警与历史任务展示。

3. RViz2 显示配置，包含地图、机器人位姿、目标工位与规划路径，以及默认视角和同屏使用说明。

4. 界面字段与数据来源对照表、任务状态映射、中文提示文案及刷新与过期参数配置。

5. 模拟数据源和异常演示场景，支持与真实 ROS 2 数据切换，界面明确标注运行模式。

6. ROS 2 Launch、依赖与环境说明、启动和操作指南、任务记录导出功能、接口版本及联调测试记录。

代码沿用现有仓库分工：监控与集成相关内容进入 ros2\-logistics\-integration；公共契约调整统一提交接口工程师，由其组织评审并协调更新 ros2\-logistics\-interfaces。本次仅编写任务书，上述内容均为后续研发交付要求，不代表已经实现。

2. 个人验收条件

- 用户能够同屏查看地图、机器人位置、运行状态、当前任务步骤和现场视频。

- 所有显示数据及输入、确认、取消和查询入口均来自接口工程师提供的统一接口清单，接口问题和变更有统一对接记录。

- 一次完整实机搬运可从用户输入追溯到最终结果，各步骤与调度反馈、真实动作一致，失败和取消后的未执行步骤不会被标为完成。

- 能区分任务已解析、等待确认、请求已提交、执行中和实际完成；能够看清任务拒绝或失败的具体原因。

- 电量、速度等已接入字段与数据源一致；未知、未接入、断连、过期和模拟状态均有明确标识。

- 画面断流、定位异常、导航失败、目标缺失、抓取失败和任务超时均能定位到对应模块或步骤，并显示已知的原因和处理提示。

- 确认和取消入口使用统一业务接口；连续点击、超时、断连和界面重启不会造成任务重复提交或自动重执行。

- 视频显示与状态更新满足第 1 周冻结的指标；加载历史或某个显示区域故障不会导致整个窗口无法操作。

- 历史任务可查询完整步骤和最终结果，导出记录能按任务 ID 关联，不以界面缓存冒充调度侧真实记录。

- 启动说明可复现，测试记录明确区分模拟、虚拟机节点运行和实机联调结果。

3. 共同验收建议

与接口工程师共用搬运验收任务，由其统一协调实机和上游数据条件。建议覆盖不少于 10 次完整实机搬运，每次核对界面步骤、机器人实际动作及最终结果。每个关键执行阶段至少一次取消测试，覆盖通信中断、状态过期、视频断流、导航失败、目标缺失、抓取失败和进程重启；需上游配合的故障场景统一由接口工程师协调。

联合运行至少 1 小时，记录界面卡顿、消息积压、状态错误、重复操作和任务记录缺失等问题。具体通过条件由技术负责人在测试前冻结。

邀请至少 1 名未参与开发的同学，在不查看终端日志的情况下，通过工作台指出“机器人当前状态、当前位置、任务当前步骤、异常原因和最终结果”，记录无法理解的内容并完成调整。仅有截图或模拟动画，不等于真实运行过程已正确展示。

---

最终岗位目标： 让用户通过监控工作台看清机器人在哪里、正在做什么、任务推进到哪一步、为什么停住以及最终是否完成，展示结果与机器人真实状态保持一致。
