## 本次排任务的进度依据

- 用户已确认：接口侧完成录音和发送，AI 端侧完成 ASR。
- 尚待核对：三方是否已经联合跑通真实录音到界面；可视化第一次任务是否通过验收。
- 仓库已有后续功能代码，只能作为复用材料，不作为三位工程师实际完成或验收通过的证据。

## 项目接口与原任务书的关系

本次整理保留六份原任务书的正文要求，不据此修改研发实现。旧任务书中的包名、Topic 和工作空间名称有示例性质，正式联调应先与[仓库接口协议](../接口协议.md)、[音频职责说明](../可视化交互组_音频接口.md)和[部署配置](../部署配置.md)逐项核对。旧文引用的独立 V1.0 协议未随本目录提供，不能直接视为与仓库现有版本一致。

已发现的待核对项：

| 项目 | 原文情况 | 第二次任务拟采用的方向 |
|---|---|---|
| 音频转换 | 接口第一次任务要求交付原始格式；AI 第一次任务有“接口工程师转换后提供”的表述 | 采集与交付归接口侧，模型所需预处理归 AI 侧；现有音频接入协议本身要求的格式由双方先验证，不能把不合规音频送入接收端 |
| 识别触发 | AI 第一次任务写接口工程师调用识别 Service；接口第一次任务又明确不编写该客户端 | 按现有项目职责：接口侧提交音频任务，AI 侧调用自己的 ASR，避免两边重复触发 |
| 消息类型 | 第一次任务示例使用 Trigger、String 和 `/interaction/` 转发 | 本项目已有 RecognizeAudio、ProcessAudio、RecognizedText 等类型；先对齐清单，不能让同一服务名同时使用两种类型 |
| 界面与数据职责 | 总任务书部分界面职责有重叠 | 接口工程师维护统一接入清单和联调；可视化工程师负责窗口与显示逻辑，按清单订阅已有公开接口，无需为每个 Topic 新建转发节点 |
| 任务书完整性 | 部分章节保留标题，但未带出表格、状态机或排期内容 | 标记为待补资料，不在整理目录时推测或补写 |
