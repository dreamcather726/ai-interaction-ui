## 二、第二周职责与验收

| 岗位 | 新增能力 | 主要验收 |
|---|---|---|
| AI 端侧 | LLM 本地部署、HTTP 调用、提示词、Schema、独立候选校验、Action 服务 | W2-02～04、08、09 |
| 接口 | 文字/语音输入统一、身份与结果校验、异步生命周期、去重/冲突/忙碌、取消与恢复 | W2-04～09、11 |
| 可视化 | 原文与候选显示、阶段/追问/错误、有限历史、文字入口、主线程安全刷新 | W2-05、10～12 |

共同主线为“直接文字/第一周 ASR → ParseTask → 经校验候选 → 窗口”。以[十二项共同验收](02_第二次任务/README.md#四共同验收)为准，T01～T08 是真实模型测试，异常替身另记。文档更新不表示新节点或模型已经完成部署。

本周限制在单轮 NAVIGATE、TRANSPORT 和明确返回要求；参数缺失先产生追问，不要求继续多轮补齐。仅生成候选并人工核对，不下发机器人运动。

## 三、依赖顺序与难度控制

1. 负责人确认 ASR 成果、环境和硬件资源；AI 岗位完成模型 HTTP 调用与固定语义样例。
2. 先约定字段、白名单、错误及终态，再并行开发 Action 服务、客户端与显示；用替身解除相互等待。
3. 先纯文字联调，后接真实录音，分别定位 ASR 错误、模型理解错误和接口错误。
4. 按共同默认超时配置：发现/Goal 应答 3 秒，HTTP 60 秒，接口等待 70 秒；资源不足时统一调整并记录。
5. 最后验证取消/迟到/恢复与连续输入，不将取消 Future 视为底层 HTTP 已停止。

不强求并发推理、持久化队列、长文件传输、多轮记忆或完整断线恢复。增加难度的重点是新增 LLM 能力和可验证的接口行为，不是一次实现所有最终功能。
