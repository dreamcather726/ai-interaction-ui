# 项目基线与后续学习、任务安排

## 一、第一次任务之后的真实基线

阶段参考项目：[RoboNeuxs/ros2-logistics-interaction](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/README.md)。2026-11-10 已通过本机现有 GitHub 登录读取，核对提交为 `b878b982a08bf2533292a2a6aa5ae8611c0e1b90`（`Consolidate project documentation into README`）。此前匿名网页 404 属于访问限制，已解决，不再作为排期阻塞。

**第二周从参考项目的实际缺口继续。** 本地 `ai-interaction-ui` 实现较完整，只作为代码阅读和后续方案参考；不能把它已有的工作台、ProcessAudio、QueryAudio、录音控制与 SenseVoiceSmall 当成参考项目的现成功能。

| 能力 | 参考项目可核实状态 | 第二周安排 |
|---|---|---|
| 公共类型 | `robot_interfaces` 0.4.0，已有 RecognizeAudio、RecognizedText、AudioProcessingState 等定义 | 复用类型；有定义不等于有运行服务 |
| ASR | `ai_asr` 实现 FunASR 包装、WAV 校验、结果与阶段发布；默认 paraformer-zh，可带 fsmn-vad／ct-punc | 完成真实模型、依赖锁定、断网加载与连续两段验证 |
| 接口调用与转发 | `interaction_interface` 已有异步 RecognitionClient、统一 launch、结构化事件转发 | 复用；补请求生命周期、忙碌与超时的操作说明及测试 |
| 文件输入 | `audio_file_sender/receiver` 经 `/audio/file_data` 传完整 WAV 分块；收齐后唯一文件落盘、自动提交识别 | 在单发送端、单文件、短录音约束下联调，明确传输限制 |
| 文件传输边界 | 最多 255 块，每块 8192 字节，约 1.99 MiB；无传输 ID、校验和、ACK | 不视为正式跨机通道，不承诺可靠投递或多发送端防串包 |
| 可视化 | `robot_visualization` 只有包骨架，setup.py 无可执行入口 | 从最小 PySide6 窗口开始，接现有两个结构化转发 Topic |
| 后续能力 | `ai_edge`、`ai_interface` 为后续开发框架；ProcessAudio、QueryAudio、ParseTask 等有公共定义，但当前无对应运行实现 | 顺延，不要求第二周一次性迁移完整本地工程 |
| 已记录验证 | README 记载 WSL 构建、10 项逻辑测试及 ROS 服务／话题／统一启动退出；ROS 联调使用固定推理结果 | 作为集成基础；真实模型、准确率、性能和断网加载不能标成已通过 |

关键源码证据：[ASR 节点](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/ai_asr/ai_asr/asr_node.py)、[模型包装](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/ai_asr/ai_asr/funasr_engine.py)、[异步客户端](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/interaction_interface/interaction_interface/recognition_client.py)、[转发节点](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/interaction_interface/interaction_interface/audio_interface_node.py)、[文件接收端](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/interaction_interface/interaction_interface/audio_file_receiver.py)、[可视化入口配置](https://github.com/RoboNeuxs/ros2-logistics-interaction/blob/b878b982a08bf2533292a2a6aa5ae8611c0e1b90/ai_interaction_ws/src/robot_visualization/setup.py)。

本次在 Windows 临时只读检出中复跑 `python -m unittest discover -s tests -v`，10 项逻辑测试通过；测试使用模型与 ROS 替身。源码核对和这次逻辑测试不代表本次已完成 WSL／设备／真实模型复验。第一周个人设备上的已完成成果可补证据后复用，不因尚未合入仓库就要求全部重写。

## 二、第二周的学习与任务目标

**用现有架构跑通两段不同真实录音文件到真实文字、再到窗口；同时把失败与未确认说清楚。** 本周允许显式指定输入 WAV，要求接收端、ASR 和窗口持续运行，收齐后自动识别，不要求尚不存在的窗口录音按钮。

| 岗位 | 学什么 | 完成什么 | 配合谁 |
|---|---|---|---|
| 接口调用 | WAV 文件完整性、异步 Future、来源 ID、忙碌与超时、QoS | 复用文件收发与 RecognitionClient，交付启动和请求追踪说明，核对两段连续输入 | AI 核对可读文件；给窗口两个真实转发端点 |
| AI 端侧 | 模型加载复用、VAD 与标点依赖、真实结果、时间与资源 | paraformer-zh 真实运行，锁定已验证版本，验证静音、格式、模型故障与恢复 | 接口交付输入；窗口按实际状态展示 |
| 可视化与监控 | Qt 事件循环、异步 ROS 接收、结构化字段、关联与过期 | 在空包中增加最小窗口及入口，按请求展示状态、文字、历史和错误 | 仅按接口岗清单接入，不调用模型 |

配套[知识点导航](../知识点/README.md)、[共同任务](02_第二次任务/README.md)和[记录模板](02_第二次任务/验收记录模板.md)。源码阅读需区分“参考项目正在运行的路径”和“本地较完整实现的学习参考”。

## 三、后续阶段安排

以下周次是建议节奏，完成上一阶段门槛后再进入。已有个人成果验收通过后直接复用，其他组真实接口未到则登记依赖，SIM 结果不代替实机验收。

| 阶段 | 知识主题 | 接口调用工程师 | AI 端侧工程师 | 可视化工程师 | 进入下一阶段的条件 |
|---|---|---|---|---|---|
| 第 2 周：真实 ASR 与窗口 | 文件、Future、模型复用、状态与文字关联 | 连续文件交接、转发与失败追踪 | 真实模型、环境锁定与异常验证 | 最小结构化结果窗口 | 两段真实录音正确对应；失败不显示旧文字，未验证项有记录 |
| 第 3 周：录音输入与受理编排 | 采集控制、AudioSegment、ProcessAudio、队列、查询 | 增加真实采集入口，确定来源 ID 与正式数据交付方式 | 增加 AI 端受理、队列、快照和模型健康信息 | 接入已经实现的录音控制、受理和补查 | 不手工换文件路径完成连续录音；同段来源可唯一确认 |
| 第 4 周：文本到候选 | 结构化输出、白名单、缺参、人工确认 | 对齐 ParseTask 和准备契约，提供可辨识的模拟准备端 | 接文本解析，校验字段与资料，不直接执行 | 文本输入、候选预览、缺参提示与显式确认 | 合法文本产生候选；缺参、格式错误和未知 ID 不执行 |
| 第 5 周：草稿与模拟执行 | 版本、确认上下文、Action 反馈与取消 | 实现准备／执行／查询适配，处理拒绝和不确定结果 | 关联草稿与候选，只按真实反馈回复 | 草稿审阅、逐步反馈和取消结果 | 已确认版本在 SIM 执行，拒绝、取消、超时可区分 |
| 第 6 周：监控与实机接口 | TF、图像时序、数据新鲜度、适配器 | 对接地图、相机、部件及已提供的导航／抓放接口 | 接真实状态查询，缺数据不编造 | 展示定位、视频和真实状态，明确过期与来源 | 来源与有效性可追溯；真实接口缺失明确登记 |
| 第 7 周：实机与恢复 | 部署、执行确认、重启与幂等边界 | 在具备接口的现场联调，验证重连不重复下发 | 验证模型故障与迟到结果，只按执行反馈回复 | 展示实机步骤、异常和补查，不自动恢复旧动作 | 约定任务得到真实执行确认；故障后安全恢复，新任务可用 |
| 第 8 周：交付 | 版本冻结、可复现环境、证据与限制 | 汇总部署和联合验收 | 汇总识别、模型与解析评估 | 汇总操作手册和异常说明 | 他人按文档复现，逐项写实际结果和限制 |

第 3 周可参考本地[音频接口](../接口与部署/可视化交互组_音频接口.md)和[部署配置](../接口与部署/部署配置.md)，第 4～5 周参考[任务草稿](../功能说明/任务草稿与长任务.md)与[复杂文本验收](../验收/复杂文本指令验收.md)。这些是后续实现材料，不替换参考项目当前的 launch、包名、默认模型和运行端点。
