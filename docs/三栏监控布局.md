# 三栏监控工作台

本轮只调整 Qt 展示与控件布局，沿用 `theme.py` 浅色配色，不增加第三方依赖，不改 ROS 节点、话题、服务或语义处理。窗口默认1440×900，屏幕较小时限制初始尺寸。左侧固定120像素，右侧固定260像素，中间随窗口拉伸。页面及长内容继续采用按钮切换，不使用主窗口滚动区。

## 页面位置

| 位置 | 内容 |
|---|---|
| 顶部64像素栏 | 机器人图标、平台标题、系统在线、AI编排连接、语音任务状态及每秒刷新的北京时间 |
| 左侧导航 | 首页、地图与定位、机器人状态、任务管理、相机图像、日志分析、系统设置 |
| 首页上排 | SLAM地图网格占位、黑色前视相机占位；放大、缩小、全屏和折叠按钮均为禁用占位 |
| 首页中排左 | 语音／文本页签、录音状态、开始／停止、控制反馈、ASR文字、候选动作和澄清提示 |
| 首页中排右 | 六步机器人流程说明、现有 PipelineStrip、当前阶段及文件说明、任务信息占位、语音阶段示意条 |
| 首页底部 | 系统日志、请求ID查询与清空按钮，右侧数据来源说明 |
| 右侧常驻栏 | 机器人、底盘、电池、网络、当前任务占位，以及六个真实服务状态徽章 |
| 任务管理 | 原 TaskDraftPanel，保留动作选择、编辑、保存、审阅、取消及草稿查询 |
| 日志分析 | 运行日志／历史记录页签；历史记录按原request_id关联结果，提供返回首页查看入口 |
| 系统设置 | 设置占位、原工位管理、物料管理及当前配置；本地保存和后台配置联动均保留 |

ASR、候选、阶段说明及日志沿用现有 PagedText，完整文字通过上一页／下一页查看。录音即时提示使用单行标签，长提示可悬停查看全文，错误及业务回执仍进入日志。历史保留100条，日志保留1000行。

首页和日志分析复用同一张日志卡片，切页只移动控件，不复制数据或重新绑定清空按钮；内容保留，分页按新的显示空间重新计算。导航切页不会重新创建草稿、历史、服务徽章或工位物料管理组件。

## 占位数据边界

地图、视频、底盘、电池、网络及机器人任务信息全部显示待接入，不写示例坐标、82%电量或虚构IP。顶部“系统在线”表示本地工作台开启，AI编排连接仍来自现有可用性消息。顶部任务状态依据已有语音处理任务是否处于阶段0～4切换，不表示机器人正在运动。

现有 PipelineStrip 的四步仍是音频接收、语音识别、语义解析与结果保存，保留原高亮逻辑。机器人六步流程仅作“待接入”说明，不能用语音识别阶段驱动导航／抓取完成标记。下方百分比是固定阶段映射的展示示意，明确标注“非机器人执行进度”，不表示真实耗时或运动完成率。

## 用户自行复测

本次只做源码审阅、编辑和格式整理，没有启动界面、ROS、模型、构建或测试。更新Ubuntu仓库后，关闭旧工作台，在工作空间根目录自行执行：

```bash
cd ~/ai-interaction-ui
source /opt/ros/humble/setup.bash
colcon build --packages-select robot_visualization
source install/setup.bash
ros2 run --prefix /usr/bin/python3 robot_visualization dashboard --ros-args \
  -p asr_python:=/usr/bin/python3
```

1. 窗口标题应为“机器人可视化与监控平台 · 三栏监控版”，启动日志的界面布局应包含“三栏监控工作台”。首页应为双列卡片，而不是原来的顶部八页布局。
2. 检查七个导航入口、高亮、右侧徽章及每秒时钟；地图、相机、底盘、电池和网络仍应显示待接入。
3. 服务就绪后开始、停止录音，核对ASR、候选、澄清问题和当前阶段；失败不能显示为机器人执行成功。长文字逐页核对。
4. 在任务管理添加未保存动作，切换全部页面再回来，草稿和输入应保留。系统设置中的工位、物料可正常新增、停用和保存。
5. 首页写入日志后切到日志分析，内容应保留，分页适应显示空间；追加日志、清空，再返回首页，不能出现两份不同步的日志。
6. 在日志分析的历史记录中选择原请求，再返回首页检查结果；请求ID查询和日志清空按钮均应工作。
7. 关闭窗口应继续等待现有后台清理，时钟和录音观察定时器随后停止。
